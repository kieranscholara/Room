# Architecture invariants

## Approved implementation update — 14 October 2026

Baseline obligations are preserved below. The following source-backed rules have now been implemented; full combined verification remains pending.

| Invariant                                                                              | Current owner and evidence                                                                                                                                                                                                                                                                                                             |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Both views consume one accepted/preview scene; no 3D edits bypass the editor           | `room-viewer-3d.tsx` uses `editor-store`; shared `sceneObjectTransform` uses right-handed +Y yaw. `renderer-contract.test.ts` compares actual Three/Konva transforms to geometry footprints without changing saved JSON.                                                                                                               |
| A model never changes canonical dimensions or transforms                               | `models.ts` requires exact declared validation/selected dimensions and matching variants. Product-level fallback requires equal current parent/variant dimensions. Actual mesh bounds may differ by max(2 cm,2%) export tolerance and are rendered unscaled from a floor-centre pivot. Stale/incompatible models use labelled proxies. |
| Approval cannot change across solver deployments or changed base scenes                | Server-owned preview envelope validates solver version, base fingerprint and approved-result fingerprint. Recomputed output must match; legacy/tampered/mismatched previews reject with 409 and no write.                                                                                                                              |
| Local runtime/test writes cannot silently use hosted Supabase                          | Exclusive `selectSupabaseTarget` uses local status only in local mode. Test preflight rejects hosted environment/file bindings and validates loopback destinations.                                                                                                                                                                    |
| Shared mutable demo requires an explicit deployment opt-in                             | `ROOMSELL_ENABLE_DEMO=1` is required by page/API/file boundary. Bounded JSON body parsing applies to enabled requests. Production settings must leave it disabled.                                                                                                                                                                     |
| Monetary display preserves every supported minor unit                                  | `formatMinorMoney` uses exact BigInt whole units and Intl fraction parts; normal, boundary, negative, JPY/KWD and locale cases are tested. Stored minor amounts/API values are unchanged.                                                                                                                                              |
| Pricing cannot invent a retailer's commercial policy                                   | All policy fields are explicit; BigInt calculations reject mixed currencies/overflow. Discounts apply to merchandise before tax; fees are not discounted. Half-up/per-line/invoice allocation rules are versioned.                                                                                                                     |
| Issued quotations survive mutable catalogue/customer/policy changes                    | Issued snapshot/source/policy/calculation are stored separately from scenes and live estimates. Issue checks expected scene/policy/source and idempotency; reads/PDF verify snapshot integrity. No inventory reservation is asserted.                                                                                                  |
| Connector writes preserve scene geometry, SKU and stable internal IDs                  | Mapped complete feed updates change only allowed price/stock/availability fields and parent projections. SQL repeats actor/tenant/revision/freshness/mapping checks under lock; failed reconciliation rolls back all catalogue updates.                                                                                                |
| Provider credentials cannot be returned to clients or redirected to arbitrary networks | Credentials are encrypted server-side with tenant-bound authenticated encryption. Manager DTOs expose presence only. HTTPS transport checks/pins public resolved addresses, denies redirects/private endpoints and bounds bytes/time.                                                                                                  |

AI locking/catalogue constraints, job execution authority, reservations/orders and marketplace publication remain required future gates. They are not fulfilled by the current 3D, pricing or connector additions.

## Baseline invariant register — historical

Status legend: **enforced** means evidence in current code/tests; **required future gate** is a target rule which has not yet been implemented/tested. This document does not imply all future gates already pass.

| Invariant                                                                         | Current evidence / future obligation                                                                                                                                                                     |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Metres/radians are canonical; display pixels never persist                        | Enforced by scene schemas, geometry functions and floor-plan pointer conversion. Existing geometry convention test passes.                                                                               |
| The scene is the single source of accepted geometry                               | Enforced by EditorService and versioned persistence. A future 3D view must derive from the same scene/preview state, without a competing store.                                                          |
| Locked positions/rotations preserve exact numeric values                          | Enforced by lockConflicts, solver candidates/final checks and acceptance; no epsilon-based lock equality. Explicit unlock or historical undo/redo is a deliberate action.                                |
| Automatic placement preserves SKU/variant/dimensions                              | Enforced by current operations and acceptance. Product lock prevents removal. No replacement operation exists today.                                                                                     |
| Rigid groups preserve relative transforms; member locks win                       | Enforced by moveUnit, member lock checks and group lock handling. Soft followers remain preferences.                                                                                                     |
| Invalid operations and discarded previews leave accepted scenes unchanged         | Enforced by pure propose plus explicit acceptance. File/service/browser tests cover this.                                                                                                                |
| Every accepted scene is schema- and geometry-valid                                | Enforced in the application service. SQL adds tenancy/identity/version/catalogue checks, not a complete independent geometry engine. All future writer runtimes must use this application boundary.      |
| Stale expected versions cannot overwrite newer locks/scenes                       | Enforced by service checks and PostgreSQL CAS. Concurrent database tests prove one success/one conflict.                                                                                                 |
| Acceptance must match the trusted preview the user approved                       | Required stronger gate: recomputation currently has no solver/version or approved-result fingerprint check across deployments. See R3/A03. Never compare against client-supplied replacement geometry.   |
| Only authorised tenant catalogue data is usable                                   | Enforced for current additions and selected assets, including under-lock new-object checks. Future connector/AI paths must resolve internal IDs through the same policy.                                 |
| Current catalogue edits do not rewrite accepted physical snapshots                | Enforced; staleness is reported. Connector reconciliation must preserve this behaviour and stable UUIDs.                                                                                                 |
| Money uses exact minor units and one explicit currency                            | Enforced by catalogue helpers and current subtotal overflow checks. Tax/discount/delivery/rounding policy and immutable issued prices are future gates. Never use live subtotal as a historical quote.   |
| Test/local configuration cannot target hosted production                          | Required missing gate: R1 demonstrates local flag does not override environment binding precedence. Reject ambiguous/mixed targets and verify local destination before network calls.                    |
| Tenant scope comes from verified identity/authorised records, not submitted roles | Enforced by auth.getUser, RLS, grants, composite FKs and checked RPCs. Customer grants restrict individual projects.                                                                                     |
| Service keys and private files stay server-only                                   | Enforced by server-only modules and private storage access. Future workers need least-scope authority and current permission rechecks; no browser/AI provider receives a service key.                    |
| Public production never exposes shared mutable demo state                         | Required missing deployment gate: demo routes are currently unauthenticated and not environment-gated. Preserve explicit local demo behaviour while closing production routes.                           |
| Both renderers agree on identity, dimensions, orientation and projected footprint | Required future gate. Current axes already align with right-handed Y-up geometry; actual 3D integration tests do not exist.                                                                              |
| AI cannot invent products/prices/dimensions or change locks                       | Required future gate. Validate a bounded intent union without lock/catalogue mutation and commit through the same authorised preview path. AI/photographs cannot mark guessed measurements as confirmed. |
| Orders/quotes consider aggregate quantity and availability policy                 | Required future gate. Current positive-stock placement does not aggregate demand or reserve inventory.                                                                                                   |
| Consumer marketplace publication never weakens retailer isolation                 | Required future gate. Explicit published offers/consumer ownership must be designed separately from current private tenant reads.                                                                        |

Any change to these semantics needs an explicit decision, compatible migration where necessary, and the matching gates in [QUALITY_GATES.md](QUALITY_GATES.md). Preserve current behaviours with characterisation tests before consolidation.
