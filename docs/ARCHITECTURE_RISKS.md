# Architecture risk register

## Photo workflow risks — current

| Risk                                           | Control                                                                                                  | Remaining acceptance                                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Wrong apparent scale from a single photograph  | Confirmed metric rectangle, convex/order checks, camera-height and reprojection bounds; no model scaling | Physical measured-room comparison; panoramas/lens distortion/incorrect marks can invalidate visual alignment |
| Existing furniture ignored in fit calculations | Explicit measured obstacle workflow; detections have no metric authority                                 | Salesperson must confirm retained footprints                                                                 |
| AI alters room architecture or wrong object    | Reviewed masks, original retained, only selected pixels composited; exact revision application           | Image quality and human review; rectangles can include unwanted background                                   |
| Incorrect product appearance                   | Authorised original-size models and labelled box fallback; fictional models explicitly illustrative      | Manufacturer-supplied models/photos for production SKUs                                                      |
| Foreground occlusion/depth errors              | Optional explicit rectangular foreground area; no automatic depth claim                                  | Silhouette segmentation/depth reconstruction is future work                                                  |
| Provider delay or spend                        | Existing queue/lease/dedupe/revocation, shared hourly AI quota, bounded requests                         | Live model access/billing and performance under actual customer photos                                       |

## Baseline risk register — historical

Audit date: 14 October 2026. Severity is impact/priority, not proof of an exploit. Confirmed behaviour, source-evidenced gaps and future design risks are distinguished. The audit found no demonstrated cross-tenant bypass in the current tested paths.

Hosted bindings can redirect purported local browser tests, or partial bindings can mix targets/keys. `playwright.config.ts` sets only the flag. No hosted bindings were present in this audit shell.                                                                       | Make local/hosted modes exclusive and fail closed on incomplete/ambiguous test targets; add destination preflight before any browser signup/write. A01/Issue 1.                                 |
| R2  | HIGH before public rollout; confirmed route source and unauthenticated runtime | `app/demo/page.tsx`, `app/api/scene/route.ts`, history route and `local-persistence.ts` expose shared mutable demo state without a production gate. POST reads the full body before the 16 KiB check. Synthetic data does not establish access to tenant projects, but this is an inappropriate public shared-write/resource endpoint.                                                                             | Explicit deployment/demo gate plus bounded streaming body validation, preserving enabled demo semantics. Current strengths reduce immediate risk: backend lock/geometry enforcement, explicit CAS, immutable versions/audit inserts, under-lock catalogue admission, role-revocation serialisation, private validated assets and real two-tenant DB tests. These should be retained.

R1/R2/R3 are the first proposed issues. R4–R12 are planned safeguards/capability gaps; R13 is a confirmed display edge case. These are proposals, not implemented changes. Hosted safety blockers are not waived by this documentation audit. See [ALIGNMENT_PLAN.md](ALIGNMENT_PLAN.md) for acceptance criteria and dependencies.
